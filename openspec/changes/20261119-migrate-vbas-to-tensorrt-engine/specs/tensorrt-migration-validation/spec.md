## ADDED Requirements

### Requirement: 每模型冻结100张样本
一致性验证 MUST 在新推理前为四模型各冻结100个不同内容SHA样本，前三模型使用学生2162池、教师使用1577池；方法为seed20261119的80随机+20历史差异，不足补随机。

#### Scenario: 生成清单
- **WHEN** 按image_id/SHA排序后对每模型固定随机序列选择样本
- **THEN** 输出每模型100行清单及SHA、来源/层次标记和抽样算法版本，内部无重复内容，跨模型可共用图片

#### Scenario: 缺少差异或类别正例
- **WHEN** 历史差异不足20或某类无正例
- **THEN** 差异层排重后补随机至100，报告类别覆盖不足，不看新测结果换图或称空输出证明该类精度

### Requirement: 模型对照条件公平且结果完整
PT/TRT对照 MUST 使用同源权重SHA、FP16及相同解码/预处理/shape/conf/IoU/max_det/NMS，保存业务聚合前NMS后检测输出。

#### Scenario: 执行100张对照
- **WHEN** 运行四模型100张并对人数同100张检查True/False NMS
- **THEN** 形成400个模型-图片配对、每后端500次正式单模型调用和两种人数口径，保存xyxy/conf/class，额外调用另计

#### Scenario: 对照来源不一致
- **WHEN** PT源SHA不等于Engine清单source SHA或预处理/参数不同
- **THEN** 阻塞正式比较并报告原因，不以不公平对照归因数值退化

### Requirement: 框匹配与差异报告可复核
工具 MUST 按同类别IoU>=0.5降序贪心一对一匹配，并完整统计所有样本/框。

#### Scenario: 输出对比报告
- **WHEN** 完成每组PT/TRT采集
- **THEN** 按模型/类输出框数、匹配/新增/缺失、IoU均值/中位/P5/最小、置信度绝对差均值/P95/最大、最大像素坐标差、计数差异图片数/最大差；无框/未匹配不丢弃，随机/富集层分开

#### Scenario: 保存差异图
- **WHEN** 存在未匹配框/计数差异或仅坐标/置信度变化
- **THEN** 前两类所有图片保存PT/TRT私有并列叠框图，后者每模型至少最大10张或不足时全部，所有逐框数据仍保留

#### Scenario: 对比完成与采用分开
- **WHEN** 各组100张完整、零运行失败、数值合法且证据备份完整
- **THEN** 只能标记对比完成；IoU匹配阈值不作验收线，用户复核差异后决定采用，无标注不宣称准确率/mAP通过

### Requirement: 服务端功能验证保持独立
系统 MUST 按源02验证项目实际Engine而非仅援引历史报告，包括三接口5901全量、几何/输入、同接口并发和混合调用。

#### Scenario: 全量和输入回归
- **WHEN** 新服务运行同Engine参考输入及Base64/dataURL/本地文件/受控URL/坏图/缺图场景
- **THEN** 业务零失败或按既定错误处理；有效输入规范化响应与旧TRT参考一致，仅去动态字段/排序，不取整浮点删差异

#### Scenario: 混合与同接口并发
- **WHEN** 执行各完整池候选I/C/b和各接口64图交替后总C3混合3轮
- **THEN** 响应与独立顺序参考一致，无参数串扰/死锁，进程完整回收

#### Scenario: 直接启动和恢复
- **WHEN** 从项目根/其他cwd在vbas-trt独立端口启动并重启、调用Health/WorkerStatus/Drain，恢复旧版本后各接口64图冒烟
- **THEN** 所有步骤有可复现证据，测试关闭外部注册且不改变线上实例

### Requirement: 有限性能与稳定性验证
系统 MUST 对三接口分别执行I1/C1/b1旧新TRT三对比较及新版30分钟闭环稳定性，seed20261118，HTTP60秒，trace off，无重试。

#### Scenario: 执行配对性能
- **WHEN** 按旧→新、新→旧、旧→新，每组预热30秒/发送300秒运行
- **THEN** 逐轮零失败，保存原始请求和窗口，报告吞吐/分位数/CPU/RSS/GPU，不平均P95或以不同窗口TPS相加

#### Scenario: 执行稳定性
- **WHEN** 每接口闭环运行30分钟
- **THEN** 有限窗口零失败，保存内存/资源时间序列并披露增长或限制，不倒推生产SLO或事后收益门槛

### Requirement: 执行保护与证据完成出口
所有执行 MUST 独立run_id留存版本/数据/配置/模型哈希及原始证据，仅使用授权GPU，不重叠活动GPU任务；工作完成与采用/部署分开。

#### Scenario: 活动任务未cleanup
- **WHEN** 实施前核查仍有旧42轮或其他同卡任务
- **THEN** 等待真实cleanup及GPU空闲后才同步/运行，不重复启动、不操作历史PID、不借卡，保留8+I×1.5GiB主机预算

#### Scenario: 异常或证据不完整
- **WHEN** 发生未知错误、同TRT业务差异、非法数值或统计不一致
- **THEN** 保存现场并阻塞对应出口，调查后新run_id复验，不改b/队列/超时或删除样本求通过

#### Scenario: 最终交接
- **WHEN** 源05任务全部有证据，整包前后源不变且本机包及每文件核验完成
- **THEN** 关联最终commit/配置/环境/Engine/样本/原始结果/回退；清理本任务进程且确认其他服务无影响，精度复核状态单列，不部署、不做C++或重建定时器

### Requirement: 执行过程中同步双清单进度
执行者 MUST 在每个OpenSpec子任务开始、实质检查点、完成或阻塞时同步更新本change tasks与源方案05-tasks.md；README记录当前阶段、07仅按真实证据更新出口，不得仅在最终交接补记。

#### Scenario: 阶段部分完成
- **WHEN** 一个聚合任务仅部分子任务完成或长时间实验尚在进行
- **THEN** OpenSpec仅勾选已完成子任务，源05保留未完成聚合复选框并记录状态、北京时间、完成数量/任务ID、实际结果、证据run_id和代码版本及下一步

#### Scenario: 验证阻塞或用户复核待定
- **WHEN** 实施、验证或差异复核仍未完成或遇到失败
- **THEN** 双清单明确记录进行中/阻塞和恢复条件，代码已写、验证通过、采用分别标注，不能因文档齐备或子任务勾选自动认定完成出口通过
