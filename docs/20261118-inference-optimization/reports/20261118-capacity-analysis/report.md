## 方法

`scripts/benchmark/summarize_capacity.py` 仅使用标准库，读取已有 case-result、load/summary、requests.jsonl 与 resources.csv，不导入推理框架、不访问GPU、不启动服务。输出独立目录，禁止覆盖；未完成轮明确列入排除清单。源码与正式服务目录隔离复制到服务器 `environment-20261118/summarize_capacity-offline.py` 试运行，不拉取或改变正在测量的服务代码。

核对请求记录数、业务成功/失败数与保存摘要，保存每份证据的字节大小和SHA256；正式版本另核对case-result内嵌摘要与负载摘要相同。异常应先检查，不能用已有摘要掩盖缺失请求。CPU/GPU统计仅取正式发送窗口，剔除启动、预热和排空。

开放式按10秒边界重建计划发送、实际发送、完成及发生器保护丢弃数量，连续3个完整窗口未解决请求数严格增长时保存区间起点与检测时点。发生器本地丢弃从未解决计数扣除，单列失败及时间，避免把发生器保护上限虚构成服务器持续积压。闭环不根据这一规则宣称撞墙，仍需跨配置平台与定速补证。

归集的请求时延是客户端单图wall-clock，不能称纯服务端推理时长；CPU按单核100%计算，服务角色为各进程之和。GPU利用率不等于FLOPS实际使用率。本轮没有生产SLO或人工标注。
