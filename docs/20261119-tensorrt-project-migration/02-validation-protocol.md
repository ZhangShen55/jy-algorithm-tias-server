# 验证协议

本协议为建议冻结方法，待方案批准后执行。比较以旧 TRT 路径为迁移主对照，PT 为历史一致性参照，不把迁移目录的收益重新计为后端加速。

## 验证矩阵与判定

规范化只去 TimeStamp、UseTimeMs、FreeCapacity 等已约定动态字段，并按历史规则排序；不取整浮点或删异常。模型原始输出数值检查 NaN/Inf、类别、置信度、框序和边界，完整记录对 PT 的既有差异。

固定 shape 的 batch1 不等于 HTTP 请求只能含一张，也不等于 MaxConcurrentBatches=1；现有业务逐图处理及准入语义必须保留。用户已确认教师Teacher_Behavior_Thresd.ImageSize只支持640，其他值加载前明确启动失败；原图分辨率可变化。以默认640完成不同图片尺寸/ROI对照，另验证1280、320、非整数和无效配置均明确失败；不静默覆盖，不改变HTTP请求/响应或阈值语义。

## 四模型各100张的一致性对比（用户2026-11-19补充）

该项独立于接口最终响应对照：必须保存每个模型在业务聚合/计数前、NMS后的检测输出（xyxy、confidence、class），不能仅比较HTTP200或最终人数。四模型各100张，即400个模型-图片配对、每后端400次正式单模型推理；人数模型额外用同一100张分别检查旧人数True、学生人数False两种agnostic_nms口径，因此执行量每后端为500次，不增加样本张数。若通过接口采集顺带运行其他模型，额外调用另记，不冒充独立样本。

### 样本冻结

- 人数、人脸、学生模型从现有2162张学生图片池选取；教师模型从1577张教师图片池选取。各模型内部按图片内容SHA去重到100个不同内容，跨模型允许使用同图。
- 先按image_id/SHA排序，再用seed20261119独立按模型抽80张；另20张从历史同模型差异样本中按image_id/SHA排序选取，排除已选内容。历史差异不足20时按相同随机序列补齐，不重复、不以新测结果挑图。
- 在任何新推理前生成并冻结四份100行清单，含模型、来源、image_id、SHA、抽样/历史差异标记，保存清单SHA。80张随机层与20张富集层分别报告，汇总不当成无偏数据集准确率。
- 报告每类是否出现正例、目标数量和场景覆盖；没有举手/站立等类别正例时明确写覆盖不足，不能将空输出一致称为该类精度通过，不临时更换样本掩盖限制。

### 公平条件

PT源权重必须与Engine manifest的source_sha256一致。PT使用FP16、同一解码图像/预处理方法、相同输入shape、conf/IoU/max_det、类别及NMS参数；逐组保存实际参数。不得用PT默认矩形预处理与TRT固定shape差异混作数值精度退化。业务原路径与同shape模型级对照分别报告。四模型固定形状见04；不改阈值或NMS求一致。

### 对比方法与输出

复用scripts/benchmark/compare.py的同类别IoU>=0.5、按IoU降序贪心一对一匹配规则，固定规则后再运行。0.5仅为框匹配口径，不能单独作为精度合格线。

每模型/每类给出：图片配对数、两端检测框数、匹配数、PT独有框、TRT新增框、匹配IoU均值/中位/P5/最小、置信度绝对差均值/P95/最大、坐标最大绝对差（像素）、计数不同图片数/最大计数差。完整保留逐图逐框结果，校验NaN/Inf、类别、置信度和几何合法性。无框样本和未匹配框均计入统计；匹配框误差的分母不得隐去未匹配框。

输出四张模型汇总表、原始两后端JSONL、逐图/逐框差异清单；所有存在未匹配框/计数差异的图片生成PT/TRT并列叠框图。仅坐标/置信度有差异时，每模型至少保存差异最大的10张（不足则全保留），其余逐框数据完整留存。私有图片不提交Git，报告给出私有证据索引和哈希。

### 出口判定

四组各100张必须齐备且零运行失败；两种人数NMS口径分别齐备；源模型/Engine/输入/配置哈希可关联，所有数值合法，新增/缺失/类别与计数差异均已分类和可复核，原始证据整包及本机逐文件核验完成，才可标记“100张对比已完成”。

“对比完成”和“同意采用”分开：出现PT/TRT差异不删除样本、不改阈值自动通过；报告具体差异及历史差异是否重现，由用户复核后决定接受或修复。缺少人工标注和预定容差，不自行设置事后准确率门槛，不宣称mAP/真实准确率通过。同Engine旧TRT迁移前后仍要求原约定的业务响应一致，不能用本项允许数值差异放宽该检查。

## 保护与停止

每轮检查 GPU UUID、空闲和原主机预算8+I×1.5GiB；不与旧42轮或其他 GPU 任务重叠，不借用其他 GPU。保留完整请求、服务日志、资源、配置、启动/清理事件。出现未知错误、业务差异或几何回归先保存并停止，调查后修改实现；复验用新 run_id，不覆盖或重跑求通过。性能差异需解释但无预设生产SLO，用户决定有限结论是否满足试用目标。

## 输入负例与混合诊断的执行口径

原学生/教师服务缺图、URL返回非图像、坏Base64在捕获异常后显式返回HTTP500及detail；请求schema缺字段返回422。本轮保持既有状态与错误详情，不改服务错误码。正常输入必须HTTP200且业务成功；预先标识的负例仅接受该场景的既定状态/详情，新旧必须一致。未知5xx或CUDA/OOM消息仍为失败，不以“负例”泛化接受任意500。

混合隔离诊断在首次运行前固定I1/C3/b3、queue0，各接口64图，先交替再三轮混合；b3仅用于允许共享模型的有限诊断，不是容量候选或默认配置，不放宽已有容量/稳定性条件。
