# 执行与对照方案

目标是执行已授权27轮测试和报告，不改推理业务/模型。先解决worker和准入两个明确参数，期间只读核查及计划草拟；不把工具支持能力当用户要求的替代。

1. 核对本机/服务器版本、SSH、GPU/主机资源、旧任务退出、现有输入/Engine指纹。保留受保护路径及旧环境，不凭旧PID发信号。
2. 根据确认的worker语义选择路线：若总worker1/2/4、每实例1，优先复用既有单worker实例管理；若每实例W1/2/4，使用显式多worker独立驱动，保留Uvicorn父进程和全部模型worker，采全部实际PID，逐worker就绪及请求覆盖、按自有进程组清理。现有instances.py不能假称已支持此路线。
3. 正式执行器默认无参只CPU打印/核验计划，显式run才启动GPU；每轮写独立配置和启动命令，关闭外部注册/trace，先CPU验证计数/分位数/窗口、进程树和回收。必要工具变化以针对性CPU回归核验，不顺带改服务或测试参数。
4. 冻结一次完整27组合计划和输入、配置及代码关联。每轮有资源守卫，逐步装载且全部实际worker就绪，预热后正式测量。正式开始/结束采用统一单调与Unix时间映射，原始请求/资源可对齐。
5. 每完成一轮独立核对计数、分位数、失败分类、PID/资源覆盖及cleanup，写case-result与journal后再下一轮。快速429导致发生器受限时明确记录，不暗中增加进程或更换调度制造收益；方案若需更改先留存受限轮并明确比较边界。
6. 全部完成或有保护停止后，离线归集九点/接口曲线、成功吞吐与尾延迟、429/异常和资源，不平均P95、不把异窗TPS相加。对于资源不足/未执行的组合保留计划和理由，不画成零吞吐测量值。
7. 完整封存、本机整包/逐文件核验，更新05/07和中文报告，提交推送perf，保持工作区干净。测量期间不拉文档提交；仅清理本任务进程，不部署/归档/重建定时任务。
