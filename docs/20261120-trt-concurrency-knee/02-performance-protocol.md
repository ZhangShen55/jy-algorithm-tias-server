接口sync/student/teacher，各自按拓扑1→2→4、每拓扑总客户端并发50→100→200各一次，27轮串行；总C不是每实例C。已冻结I=1/2/4，每实例W=1，总模型进程数为1/2/4；每worker b=512、queue=0。

其余统一测量方法：闭环HTTP、一请求一图、完整池sync/student各2162图/teacher1577图，seed20261118；每轮全部实际worker就绪后预热30秒、正式发送180秒、单请求HTTP timeout60秒、停止发送后有界排空，无重试。正式轮各一次，不追加重复窗口或更大C；如需改变窗口/方法先回写协议，保持同一比较组一致。正式测量使用trace off，普通请求成功字段校验，不混入audit/trace容量成绩。

所有模型worker须在开始前完成四模型warmup。HTTP keepalive可能固定到worker，预热和就绪须记录每个实际worker覆盖，不能只看到某一worker Health200就称全部就绪。多实例负载分配及每端口/实际worker请求数留证，不宣称Uvicorn天然均匀。正式前记录调度方法及发生器进程数，比较组不混用不同发生器配置。

## 主指标

成功吞吐 = 正式180秒内HTTP及业务均成功且已完成的图片数/180。另报排空后最终成功、失败和排空耗时，不能把窗口外完成算进正式TPS。成功请求P50/P95/P99/均值从原始请求计算；429等失败延迟分开，全请求低P95不代替有效图片延迟。记录已发/窗口内完成/窗口结束在途/排空，按状态和业务成功字段核对。

资源按统一正式窗口过滤，采GPU显存/利用率/温度/功耗、服务全部实际worker CPU/RSS、管理父进程和所有实际发生器PID；CPU单核100%口径，保留原始样本。记录发生器CPU饱和与成功/拒绝占比，客户端受限时不得宣称服务硬峰值。

## 拐点与结论限制

每接口/固定拓扑比较C50→100、100→200成功TPS增幅和成功延迟、拒绝率、GPU/CPU。完整展示增幅；可将成功TPS增幅小于5%且延迟/拒绝或资源代价上升标为“本次网格内的平台候选”，仅描述性规则，不是生产验收线。单轮波动不证明精确拐点，也不用于宣布5%以内没有收益。

若三档已全部饱和，只能说拐点可能位于C50或更低，不能定位精确C；若C200仍明显增长，只能说网格未找到平台，不能宣布C200峰值。多实例同时改变worker数量时，不能分离实例数与worker数的因果贡献。b512/queue0是用户明确的新条件，高C造成的内部等待和失败按原始记录保留；429若出现须额外调查，成功吞吐和资源共同解释，不以快速拒绝RPS冒充处理能力。

## 失败与保护

预期429必须响应为既定满载信息并与实际worker日志、b上限一致；503须区分排空、队列/配置原因，按原始证据归因。所有失败及本地保护完整保留，失败点只作诊断、不推荐为有限零失败配置。未知传输/业务/HTTP错误、OOM/CUDA错误、worker退出或统计/资源覆盖不完整，保存现场并停止后续轮调查，不自动覆盖重跑、不放宽超时/队列/b求通过。资源预算不满足者明确记录未执行原因，不伪称完成轮。
